# 影之刃零 存档系统逆向笔记

记录本次模组开发中通过 UE4SS 探针摸索出来的存档系统结构，以及尝试过但失败的路径。
供后来者少走弯路。

环境：

- 游戏：Phantom Blade Zero，UE **5.7**，Steam 版（Shipping 构建）
- 框架：UE4SS `v3.0.1-1195-g1ceefac8`（KintaroModding PBZ 分支）
- 存档目录：`...\ProjectPBZ\Saved\SaveGames\Steam\<SteamID>\`
- 存档文件：`PBZSaveGame.sav`，自定义头 `50 42 5A 53`（`PBZS`），非标准 GVAS

## 二、验证可用的调用

### 存档

```lua
local ss = FindFirstOf("PBZSaveLoadSubsystem")
local result = ss:TrySave(4, {}, nil)   -- 4 = ManualSave
```

实测返回 `0`（`SavedNow`），存档文件确实被写入（体积 742KB → 1188KB），时间戳吻合。

### 传送

```lua
local cm = FindFirstOf("PBZCheatManager")
cm:GM_TeleportToLocation({ X = 10000.0, Y = 20000.0, Z = 500.0 })
```

实测坐标确实被修改（Z 变化 400 单位后自由落体回到地面）。

### 读取玩家坐标

```lua
local pc = FindFirstOf("PlayerController")
local pawn = pc.Pawn
local loc = pawn:K2_GetActorLocation()   -- {X, Y, Z}
```

注意：**主菜单没有 Pawn**，必须在关卡内调用。

## 三、失败的路径与现象

### 1. `LoadGame(SlotName, {})` —— 进了函数但立刻返回

钩子能看到入口命中：

```
命中 LoadGame 入口
（之后什么都没有）
```

而游戏自己读档时：

```
命中 LoadGame 入口
命中 → LoadAdvancedSaveGame
```

同一个函数，游戏继续走，我们停住。

**根因（关键）**：第二个参数是 **Out 参数**。用抓到的对象重放时报错原文：

```
Tried storing reference to a Lua table for an 'Out' parameter when calling a
UFunction but no table was on the stack
```

UE4SS 的 Lua API 只能给 Out 参数传一张 Lua 表，游戏拿到的是全零结构体。
推测函数内部检查了该结构体的状态字段后直接 `return`。

### 2. `GM_LoadGame(SlotName)` —— 完全空操作

传 `""`、`"PBZSaveGame"`、`"AutoSave0"` 都返回 `nil`，不触发地图加载，不报错。

### 3. `ArmForSaveSlot(pawn, slot, 0..4)` —— 无效

五个 Trigger 值逐个试，`IsDestinationLoadingActive` 前后都返回 `nil`（连 `false` 都不是），
`ArmForSaveSlot` 无异常、无返回值、无副作用。

推测这套 `Arm*` 是给关卡间旅行用的，不是给读档用的。

### 4. `LoadGameFromSlot(slot, {})` —— 返回 `true` 但没有后续

返回 `true` 大概率表示"数据已从磁盘读入内存"，但画面不动、不触发地图加载。
说明还缺"触发关卡切换"这一步，而这一步没找到入口。

### 5. 暂停后读档 —— 无效

```lua
GameplayStatics:SetGamePaused(pawn, true)   -- 返回 true
ss:LoadGame(slot, {})
```

依然停在 `LoadGame` 入口。

### 6. 死亡重生 —— 不会重载存档

`GM_KillPlayer` 执行后角色确实死亡，但没有地图加载。
说明本作死亡是"回到检查点继续"，**不读档**，世界状态保留在内存里。

### 7. 重放游戏自己的参数对象 —— 报错

见上文 Out 参数错误。捕获到的槽名字符串也是**空的**，说明槽名不由第一个参数传。

## 四、结论

在 **UE4SS Lua 层面**，本作的游戏内读档走不通，原因是：

1. `LoadGame` 依赖一个 Out 结构体参数，Lua 层无法提供合法实例；
2. 游戏有隐藏的门禁/状态机，静默拒绝外部调用。

**可行的替代方案**：`TrySave` 写入的就是「继续」槽，所以
「退出到主菜单 → 继续」等价于读档，只是多花 30 秒。

**若一定要做游戏内热键读档**，方向是用 **C++ DLL**（UE4SS 的 C++ Modding API），
在原生层正确构造 `LoadGameResultParam` 并调用。工程量比 Lua 方案大一个数量级。

## 五、踩过的坑

- **不要在启动阶段 `ForEachFunction` / `ForEachProperty` 遍历类结构** —— 会导致游戏
  在启动后几十毫秒内 Fatal Error（本次实测崩溃过两次）。
  需要枚举时放到按键触发，并且逐步 `pcall`。
- **`FindFirstOf("PBZSaveLoadSubsystem")` 在启动瞬间拿不到** —— 要等进入关卡后再查。
- **`RegisterKeyBind` 的回调里不要在回调函数中 `return false`** —— 部分 UE4SS 版本会
  把它当成"停止遍历"。
- **Lua 表转结构体在本作不生效** —— 传 `SaveGameParam{ SaveSlotName = "x" }` 进去，
  手动存档数不增加，说明字段没写进去。所有依赖结构体字段的 API 都因此受限。
